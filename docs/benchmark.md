# 500 TPS 持续上报基准测试

**测试日期：2026-11-13。** 在下述环境与负载下，服务完成了连续 **1,200.727 秒**的500 TPS目标测试，实际新逻辑上报到达率为 **499.91条/秒**，并消化了起始积压。该结果验证当时的服务构建持续处理与积压恢复能力，不代表最大吞吐或零错误率。此历史测试使用了已移除的匿名注册与当时的日快照结构，不能作为当前 GitHub 注册、多上报端协议或数据库结构的容量声明。

## 负载与测试方法

采用可复现的随机开放式到达：新任务生成不等待此前请求完成。一次**逻辑上报**对应确定客户端、日期、版本和内容的累计快照；HTTP重试不增加逻辑上报数量，也不重复计入有效吞吐。

- 初始数据包含10,000个客户端身份及90天形状的历史预填；确认段内身份数从 **14,575增长到20,622**，新增6,047个身份通过真实注册API创建。
- 原测试生成规则（历史结果，并非当前无 tier 协议的容量声明）：约10%的热点客户端承担50%的更新；轻/中/重客户端比例60%/30%/10%，其模型×tier组合数上限分别在1–4、5–16、17–48内选取；实际日快照可更少，并随更新增长。每次更新1–4个组合，以完整累计快照上报；约1%的更新新增身份，日期分布约90%当日、10%前一日。
- 测量阶段新建快照（含收尾）的工具分桶统计上界：请求体P50≤1,344 B、P95≤7,808 B、P99≤14,208 B，不含HTTP/SSH协议开销。这些是分桶上界，不是精确分位值。
- 起始含 **16,330条待确认上报**，另注入 **2,500条标记积压**，同时维持500条/秒的新普通上报目标。
- 发生器最大在途请求4,096、待处理上限100,000（非客户端数）；同一上报保留版本与内容重试，单条任务最多512次HTTP尝试（含首次），指数退避封顶15秒并遵守更长的`Retry-After`。

为测量处理能力，使用以下测试专用限流配置，而非默认部署配置：

| 限流项 | 测试值 |
|---|---|
| 全局上报 | 间隔10 µs，burst 100,000 |
| 单客户端上报 | 间隔100 µs，burst 1,000 |
| 注册来源 / 全局 | 各60,000次 / 1分钟窗口 |
| 注册创建上限 | 每小时、每日各1,000,000 |

## 吞吐与请求结果

统计窗口为 **11:39:21.645713–11:59:22.372837 UTC**，持续1,200.727秒。以下计数均属于该窗口；标记积压不计入普通新输入速率。

| 指标 | 结果 |
|---|---:|
| 普通新逻辑上报 | 600,254条；**499.91条/秒** |
| 正确ACK，含积压恢复 | 619,077条；**515.59条/秒** |
| HTTP请求发起总数 | **708,155次** |
| 上报HTTP尝试 / 注册HTTP请求 | 702,108 / 6,047次 |
| 上报尝试中属于重试的次数 | 84,445次 |
| 已收到的上报响应 | 702,101次 |
| 上报200且版本匹配 / 503 | 619,077 / **83,024次** |
| 503占已收到上报响应比例 | **11.83%** |
| 注册结果 | 6,047次，全部201 |
| 评估截止在途上报 | 7条 |
| 确认期缓存代际变化 | **4次** |

ACK速率高于新输入速率，是因为同时消化了旧积压，不能将515.59条/秒解释为已验证的新输入能力。

### 积压恢复与503分布

| 阶段 | 时长 | 已收到上报响应 | 503次数 | 503占比 |
|---|---:|---:|---:|---:|
| 起始至首次采样清空积压 | 185.727秒 | 193,435 | 81,945 | **42.36%** |
| 首次清空后继续输入 | 1,015.000秒 | 508,666 | 1,079 | **0.212%** |

98.70%的503发生在消债前段。清空后实际普通输入约500.09条/秒、正确ACK约500.09条/秒；最后约61秒仍出现968次503，占该窗上报响应约3.08%，存在短时突发。

积压采样峰值为19,790条，约3分06秒首次采样为0；之后采样中位数5条、P99为114条、峰值396条。评估截止剩7条在途；停压收尾后剩 **6条未确认**，其中3条已提交数据库但ACK状态不确定，均未计作成功。

## 端到端延迟

延迟定义为本段新普通上报的**计划到达至正确ACK**，包含排队、注册、重试及退避，不包括起始旧积压和额外标记积压。仅统计评估截止已确认样本，7条在途样本未纳入；百分位采用nearest-rank。

| 样本范围 | 已确认样本数 | P50 | P95 | P99 | 最大值 |
|---|---:|---:|---:|---:|---:|
| 整个确认段的新普通上报 | 600,247 | 14.24 ms | **2.24 s** | **42.91 s** | 169.57 s |
| 首次清空后新到达的普通上报 | 507,584 | 11.44 ms | 89.36 ms | 205.34 ms | 9.14 s |

消债阶段的尾延迟明显增加。持续处理能力通过，不等于低延迟或低HTTP错误率指标通过。

## 结论与适用范围

本次结果确认：在上述数据规模、负载分布、重试机制、限流配置和SSH通路下，服务可以持续20分钟处理约 **500个新逻辑上报/秒**，并恢复起始积压。

该结果**不是最大吞吐、零503或长期稳定性保证**，不适用于任意快照大小；90天历史预填也不等于90天运行验证。真实客户端的超时与重试策略、生产默认限流、存储和网络条件均可能改变实际表现。测试方法与工具说明见[容量测试工具](capacity-tool.md)。
