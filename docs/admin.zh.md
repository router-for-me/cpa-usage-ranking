# 管理员控制台

[English](admin.md) · [返回 README](../README.zh.md)

管理员控制台默认关闭，公开排行榜与客户端上报无需启用后台即可独立运行。

## 启用与登录

在 `RANKING_WEB_DIR` 之外准备私有 JSON 配置文件，设置 `RANKING_ADMIN_CONFIG_FILE` 并重启服务：

```json
{
  "username": "admin",
  "password": "replace-with-strong-password-12-to-72-bytes"
}
```

- **用户名**：`3`–`64` 位 ASCII 字母、数字、`_`、`.`、`-`，首字符为字母或数字（区分大小写）。
- **密码**：`12`–`72` 字节（bcrypt 上限），无默认密码。
- **文件权限**：建议设为 `0600` 或 `0640`（或服务身份可读的更严格只读权限，如 `0400`/`0440`）；权限过宽时仅在启动日志输出警告而不再阻止启动。配置文件仍不得位于 `RANKING_WEB_DIR` 内（符号链接指向其中同样拒绝）。配置缺失或格式非法会阻止启动且不回显文件内容。账号变更需修改文件并重启生效（不支持热更新）。

启用后，页面顶部显示**登录**，登录后切换为**控制台**（`/admin/leaderboards`）。`GET /v1/admin/session` 对未登录访问仅返回后台启用与登录状态。

## 普通管理员管理

主管理员（配置账号）可访问 `/admin/accounts` 查看、新增或删除存储在 SQLite `admin_accounts` 中的普通管理员（仅保存 bcrypt 哈希）。

- 普通管理员无权查看或增删管理员账号。
- 用户名唯一，主管理员用户名为保留名（重启时若与已有普通管理员重名将拒绝启动）。
- 删除普通管理员会立即撤销其全部活跃会话；同名重建会分配新 ID，无法继承旧 Cookie。忘记密码时由主管理员删除重建。账号在重启后保留，会话不保留。

## 用户检索与榜单治理

主管理员与普通管理员均可访问 `/admin/users` 与 `/admin/leaderboards`。

- **用户管理（`/admin/users`）**：列出所有已注册席位（含未上报、正常、封禁及主动退出席位，不含管理员账号），显示内部 ID、头像/昵称、注册 UTC 时间、封禁与下榜状态。单个搜索框同时支持昵称字面子串与精确数字 ID 查询，采用游标分页（默认每页 `50` 条，接口上限 `100` 条），绝不返回凭据、摘要或日报正文。
- **封禁 / 解封（`disabled`）**：作用于该 `client_id` 席位及其全部上报端（同一 GitHub 账号下其他 `server_id` 的席位不受影响）。封禁后拒绝后续上报（包括已鉴权但尚在等待最终写事务的请求），并从全部五榜、六个后端周期及评分参考样本中排除，不删除历史统计。状态接口显式设置 `disabled: true/false`（幂等）。
- **下榜 / 恢复（`ranking_hidden`）**：位于 `/admin/leaderboards` 的**当前榜单**与**已下榜用户**视图。下榜在评分**之前**将该席位从全部五榜、六个后端周期及参考样本中排除，但仍继续接收其每日上报，直到管理员手动恢复；跨自然周期或重启不会自动清除。

### 管理状态矩阵（未主动退出时）

| 封禁（`disabled`） | 下榜（`ranking_hidden`） | 是否允许上报 | 参榜资格 |
| --- | --- | --- | --- |
| 否 | 否 | 允许 | 按标准规则参榜 |
| 否 | 是 | 允许 | 不参榜 |
| 是 | 否 | 拒绝 | 不参榜 |
| 是 | 是 | 拒绝 | 不参榜 |

- 封禁与下榜标志彼此独立：解封不会自动清除下榜标记；同时被封禁且下榜的席位须先解封，再恢复上榜（封禁期间直接清除 `ranking_hidden` 返回 `409 client_banned`）。
- 客户端[主动退出](integration.zh.md#退出席位withdraw)独立于管理状态：解封与取消下榜均不会清除 `withdrawn`。未被封禁时，用户可用同一 GitHub 账号和 `server_id` 重新注册以恢复原席位；`ranking_hidden` 保持不变。
- **缓存刷新**：管理状态变更、席位退出或恢复提交后，都会通知缓存 worker 提前合并重建全部周期并原子发布。写入成功不等于新缓存已立即可见，界面上的“刷新榜单”按钮也仅重新拉取已发布缓存；构建失败保留上一轮完整缓存。控制台不提供改分、清数据、删席位或恢复退出席位功能。
- **关闭后台**：移除 `RANKING_ADMIN_CONFIG_FILE` 并重启即可；数据库中的普通管理员和封禁/下榜状态会保留并继续生效。

## 会话安全与 Docker 挂载

- **会话与 CSRF**：服务端内存会话固定 `8h`（最多 `1024` 个活跃会话，重启后清空）。Cookie 默认 `HttpOnly`、`SameSite=Strict`、`Secure`。登录（`POST /v1/admin/session`）仅要求同源 JSON；登出及所有已登录的管理写请求均须同时通过同源校验与会话 CSRF 令牌校验。客户端 Bearer 凭据不可用于管理登录。
- **登录限流**：每来源每分钟 `5` 次、全站每分钟 `40` 次，复用部署的可信代理与 IPv6 `/64` 来源解析规则（与客户端注册限流独立，详见[部署、配置与运维指南](deployment.zh.md#反向代理安全与来源识别)）。
- **HTTPS 要求**：生产环境必须经由列入 `RANKING_TRUSTED_PROXIES` 的受信任 HTTPS 反向代理访问，代理须正确透传 `Host` 与 `X-Forwarded-Proto: https`。仅本地或容器隔离 HTTP 测试可显式设置 `RANKING_ADMIN_ALLOW_INSECURE_LOCAL_HTTP=true`（允许 HTTP 同源 Cookie 与会话，仍严格校验 `Origin` 与 `X-CSRF-Token`；切勿对公网开启）。

### Docker 只读挂载示例

容器以 UID/GID `10001:10001` 运行。在宿主机准备好可供 `10001` 读取的文件（例如 `root:10001`、`0640`，且父目录可遍历）并以只读方式挂载，切勿将真实配置打入镜像：

```yaml
volumes:
  - /etc/cpa-ranking/admin.json:/etc/cpa-ranking/admin.json:ro
environment:
  RANKING_ADMIN_CONFIG_FILE: /etc/cpa-ranking/admin.json
```
